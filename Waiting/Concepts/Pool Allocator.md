Pool Allocators are basically pools that have multiple block of memory, each of the same size. The idea of it is simple. As the blocks of memory are of the same size, often pool allocators are used specifically for structures used frequently in the program. A linked list containing all the blocks of memories as its nodes is available for the program. The program can borrow a block to store the structure. As it is only a change in pointers, it is a constant time operation. When memory is freed from a block, the block is just returned back to the linked list. Again, just a change in pointers, so is still constant time. The problem, one might point out, is the storage of the pointer to the next node. Wouldn't that take extra space? Well, yes, but there is a simple workaround. As the linked list contains 'free' memory blocks, one can store the pointers themselves within the memory blocks, thus bypassing the need for extra storage.
